## Initial findings — resolved in scoped re-review below

### P2 — CSRF control can enter preauth after support expiry crosses the gate boundary

`backend/app/identity/routes.py:80-87` catches authenticate's 401 and proceeds to preauth creation and session-cookie deletion without checking the bound support flow flag. `backend/app/support/gate.py:141` sets request.state.support_no_touch for bound support before the endpoint. A valid final gate clock can be immediately followed by an expired endpoint authenticate clock, so the narrow real-operator CSRF control falls back to a different authentication flow despite the explicit contract prohibition. The endpoint can return a preauth token/delete the operator cookie rather than rejecting and allowing the post-rollback observer to persist typed support termination.

Requested correction: rethrow authentication failure for a flagged bound support control, or equivalent explicit bound-control state. Deterministic regression should keep the gate valid, cross absolute/idle expiry at endpoint authenticate, assert no operator session cookie deletion/preauth response, and assert support terminal state/audit observed through the safe independent boundary. Owner fixes pending at this checkpoint.

### P2 — Support write denial audit loses known real operator and support scope

`backend/app/support/gate.py:check_request` rejects blocked business operations before route authentication; it never populates request.state.principal. `backend/app/main.py:api_error` records only generic auth.request.denied with actor/role read from that missing principal. `backend/app/identity/sessions.py:record_access` has no support/tenant/contract/environment binding inputs. Therefore an authenticated support parent/child/contextless write denial is recorded with null actor_id/actor_role and no support provenance even though the gate has validated an own bound support row. The approved Phase 8 plan requires denial audit alongside lifecycle audit, and operator identity must remain accountable.

Requested correction: retain a sanitized, server-validated denial provenance record from the bound flow (real operator, bound support role/id, tenant/contract/environment, request id and deny code), and use it in the independent denial trail. Header ids alone must never create attributed identity for a foreign or mismatched HTTP binding. Add assertions for denied parent/child/contextless writes and the foreign HTTP/session case. Owner fixes pending at this checkpoint.
